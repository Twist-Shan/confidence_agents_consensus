# 四组局部 confidence 对照：Luna pilot

运行日期：2026-09-18。20260922 是随机化 seed，不是日期。

**结论：在当前任务、模型配置和提示下，没有观察到“把高置信度分给错误答案会提高错误选择率”的明确证据。主要配对效应为 −1.71 个百分点，描述性 95% bootstrap 区间为 [−8.55, +5.13] 个百分点。不能据此证明 confidence 无效，也不应把负点估计解读为错误高分有益。**

## 固定设计

- 使用完整冻结题库 data/logic-l2-balanced-20260921.json，40 道逻辑 L2 题，无按干预结果选题。
- 正确语义 Yes/No 各 20 道，各类内 A/B 正确选项各 10 道。
- 每个“语义真值×正确选项”单元内，自身初始答案正确/错误各半；全题库自身答案正确 20 题、错误 20 题。
- 每题四条预设同伴报告，两条正确、两条错误。自身答案也是预设输入，并非模型上一轮实际回答。每次只有一个接收者调用，不是六个 agent 多轮讨论。
- 同一题的题面、自身答案、同伴身份、答案及顺序在四组间固定，只有 confidence 字段变化。
- correct_high：正确报告 .95、错误报告 .55；wrong_high 对调。equal 全部 .75，hidden 不展示分数。
- 四组各重复三次，共 40×4×3=480 个预定请求。每题十二次调用的顺序预先随机化；四题并发，均为独立无历史调用。
- 模型 openai/gpt-5.6-luna，8192 输出 token 上限，reasoning.effort=medium，strict JSON，只输出 answer。提示仍明确说明同伴可能出错，展示分数不是保证。
- 分析规则、上下文及源码 hash 在首次调用前写入 manifest。23 项自动化测试通过。结束后对全部 480 条请求正文进行核对，确认同题内只变动 confidence。

## 结果

下表错误率先计算每题每组的有效响应错误比例，再对 40 题等权平均。wrong_high 有一条缺失，因此其错误率不等于简单的 26/119。

| 条件 | 有效响应 | 错误回答 | 按题等权错误率 |
|---|---:|---:|---:|
| 正确方高分 | 120 | 28 | 23.3% |
| 错误方高分 | 119 | 26 | 21.7% |
| 全部等分 | 120 | 24 | 20.0% |
| 隐藏分数 | 120 | 33 | 27.5% |

主要比较为错误方高分减去正确方高分，只使用两组各三次响应均有效的 39 道题：

- 配对错误率差：−0.017094，即 **−1.71 个百分点**。
- 按题聚类、保持语义/选项/自身状态分层的 2000 次配对 bootstrap 描述区间：**[−8.55, +5.13] 个百分点**。
- 39 题中，8 题差值为正、8 题为负、23 题为零。每组仅三次，零差值不证明该题完全不受分数影响。
- 区间跨零，目前不足以支持预期方向的总体影响。这不是等效性检验，不能宣称效应严格为零。

equal、hidden 是次要描述性对照；未对其组间差异做确认性结论。不能从 hidden 错误率较高这一张表直接断言“展示任何置信度都能改善表现”。

## 中断与缺失处理

终端进程在收尾阶段意外退出。核对后发现 476 条已保存完整响应、1 条 pending 请求无响应记录、3 条尚未发送。确认原 Python 进程已结束后，使用 scripts/recover_local_replay.py 仅发送那三条未开始的请求，不重发 pending 请求。

缺失调用：local/luna/cal-20260921-logic-L2-v24/wrong_high/1。原始 pending 文件保留，并写入 recovery.json。它是运行中断导致的未观测响应，不是模型格式失败或拒答；summary 通用 invalid 字段对此计为一条不可用响应。

最终 480 次计划内尝试中，479 条响应可观察且全部格式有效、finish_reason=stop，没有观察到截断。第 480 条结果及费用未知，不能声称其也成功。

对全部 40 题，把唯一缺失响应分别赋为正确或错误，观察到的配对点估计界限是 **[−1.67, −0.83] 个百分点**。这只是缺失响应的敏感性界限，**不是抽样不确定性区间**，不应代替上面的 bootstrap 区间。补完三条请求的时间晚于其他调用，也应作为本次运行的操作限制保留。

## 运行质量与成本

- 479 条可观察响应均报告供应商 OpenAI。
- 可观察响应输出 token 最大值为 2743；3 次超过旧的 2048 上限，均正常结束。这支持继续保留额外 token 余量，但不能保证其他提示以后不截断。
- 可观察响应的 usage.cost 合计 **0.5985618 USD**；一条中断请求费用缺失，最终以账单为准。
- 从首次请求到恢复后最后响应约 1690.5 秒，即 28 分 10 秒，包含终端中断及恢复耗时。

## 科研解释及后续

目前最稳妥的表述是：**在这个平衡逻辑题库、四条持平的同伴报告、带谨慎提示的单轮判断场景中，尚未观察到错误高分导致错误率增加的明确证据。**这不等于模型完全忽略分数，也不代表所有真实 agent 工作流中数值置信度无效。

题目是人工逻辑任务，同伴及自身答案是预设的，模型可以重新独立解题；没有同伴理由、证据或真实工具结果。自信的自然语言表达和数值分数也不等价。本轮是局部影响 L，不足以推出多轮共识 C 的结论。

建议先保留并复现这一结果，不因点估计未符合预期就挑题或追加采样。若下一步更换提示、增加理由或改变任务，应事先定义为新的协议，并保留本轮作为对照；暂不据此大规模启动多轮传播实验。
